# 📘 ТЕХНИЧЕСКОЕ ЗАДАНИЕ (ТЗ) И ПЛАН РЕАЛИЗАЦИИ
## Проект: "SOL/USDT Trading Laboratory Terminal"

---

## ЧАСТЬ 1. ТЕХНИЧЕСКОЕ ЗАДАНИЕ

### 1.1. Общие сведения и цели
**Цель проекта:** Создание масштабируемой веб-лаборатории для разработки, тестирования, оптимизации и мониторинга алгоритмических торговых стратегий на рынке криптовалют (на примере SOL/USDT).
**Ключевые принципы:**
- **Модульность:** Frontend разбит на независимые окна (вкладки), Backend — на изолированные сервисы.
- **Изоляция стратегий:** Каждая стратегия работает в отдельном процессе, что гарантирует стабильность ядра системы.
- **Масштабируемость:** Архитектура должна поддерживать добавление новых активов, режимов и типов аналитики без переписывания ядра.

---

### 1.2. Архитектура системы

#### 🌐 Frontend (Клиентская часть)
- **Технологии:** HTML5, CSS3 (Glassmorphism/Sci-Fi стиль), Vanilla JS (или легкий фреймворк в будущем).
- **Структура:** Каждое крупное окно (Мониторинг, Стратегия, Оптимизация, Логи) имеет свой собственный набор файлов `window_name.html`, `window_name.css`, `window_name.js`. Они подгружаются динамически или через роутинг FastAPI.
- **Связь с Backend:** REST API для команд, **WebSockets** для получения данных в реальном времени (свечи, логи, состояние счёта).

#### ⚙️ Backend (Серверная часть)
- **Технологии:** Python 3.10+, FastAPI (асинхронный веб-сервер), Uvicorn.
- **Ядро (Core):** Управление состоянием, роутинг, диспетчер процессов стратегий.
- **Диспетчер Стратегий (Strategy Manager):** Отвечает за запуск `.py` файлов стратегий в изолированных процессах (`multiprocessing` или `subprocess`), передачу им JSON-настроек и сбор результатов.

#### 💾 Хранилище данных
- **Оперативная память (RAM):** Хранение состояния текущей свечи, активных задач, статуса стратегий.
- **CSV / Parquet файлы:**
  - `market_data/` — исторические и текущие данные рынка (разные файлы для разных режимов).
  - `results/` — результаты бэктестов и оптимизаций.
- **Логи:** Текстовые файлы с ротацией, разделенные по типам (системные, стратегий, ошибок).

---

### 1.3. Функциональные требования по окнам (вкладкам)

#### 🖥️ Окно 1: МОНИТОРИНГ (Monitoring)
*Главный экран трейдера во время работы стратегии.*
- **Центральная таблица:**
  - Отображение свечей в реальном времени (или последовательно при симуляции).
  - **Новый столбец "Состояние сделки"**: отображает текущий сигнал стратегии (LONG / SHORT / FLAT / PENDING).
- **Правая панель (Статистика):**
  - Название активной стратегии (подтягивается из Окна 2).
  - Состояние счёта: Начальный капитал, Текущий баланс, PnL (абсолютный и %), Количество сделок, WinRate, Просадка (Drawdown).
- **Панель управления режимами:**
  - Кнопки выбора режима: `[Симуляция]` `[Бэктест]` `[Оптимизация]`.
  - Индикатор текущего режима (цветовая подсветка или бейдж).

#### 🧠 Окно 2: СТРАТЕГИЯ (Strategy Lab)
*Место подготовки и запуска стратегий.*
- **Селектор стратегии:** Выпадающий список или карточки доступных `.py` файлов из папки `strategies/`.
- **Селектор шаблона:** Выбор JSON-файла с настройками из папки `configs/`.
- **Кнопка "РЕАЛИЗОВАТЬ":**
  - Передает связку (Стратегия + JSON) в Диспетчер.
  - Активирует Окно 1, меняет заголовок актива на `SOL/USDT [Strat_Name]`.
- **Панель результатов:**
  - Вывод логов работы стратегии в реальном времени.
  - Кнопка "Экспорт отчета" (сохранение результатов в CSV/Excel).

#### 🧬 Окно 3: ОПТИМИЗАЦИЯ И НАСТРОЙКИ (Optimization & Configs)
*Создание шаблонов и запуск генетических алгоритмов.*
- **Редактор JSON:** Визуальный интерфейс для создания и редактирования шаблонов настроек (с сохранением в `configs/`).
- **Панель Оптимизации:**
  - Выбор стратегии и базового шаблона.
  - Указание диапазонов дат (один или несколько окон для сдвигающегося окна).
  - Настройка параметров генетического алгоритма (популяция, мутация, поколения).
- **Визуализация процесса (Предложение реализации):**
  - *Таблица поколений:* Поколение | Лучший PnL | Средний PnL | Элитные параметры.
  - *График сходимости:* Линейный график, показывающий, как улучшается результат от поколения к поколению.
  - *Лог оптимизации:* Поток сообщений о ходе вычислений.

#### 📜 Окно 4: ЛОГИ (Logs)
*Центр управления информацией.*
- Фильтры по типу лога: Системные, Стратегии, Ошибки, Сделки.
- Возможность просмотра в реальном времени или выгрузки архивных файлов.

---

### 1.4. Режимы работы (Движок тестирования)

1. **Симуляция реальной торговли (Live Simulation):**
   - Данные берутся из `current_candle.csv` (или WebSocket Bybit).
   - Движок "проигрывает" свечи последовательно, имитируя реальное время.
   - Учитываются комиссии биржи и проскальзывание.
2. **Большой бэктест (Backtest):**
   - Загрузка исторического куска из `market_data/` по указанным датам.
   - Мгновенный прогон всех свечей через стратегию.
   - Формирование детального отчета.
3. **Оптимизация (Optimization / Walk-Forward):**
   - Запуск генетического алгоритма (или grid search).
   - Разбиение данных на обучающую и тестовую выборки (сдвигающееся окно).
   - Сохранение лучших параметров в новый JSON-шаблон.

## ЧАСТЬ 2. ПОСЛЕДОВАТЕЛЬНЫЙ ПЛАН РЕАЛИЗАЦИИ

Проект разбит на **8 Фаз**. Каждая фаза заканчивается работающим прототипом, который можно тестировать.

### 🟢 ФАЗА 1: Фундамент и Архитектура (Текущий этап)
**Цель:** Подготовить скелет проекта для масштабирования.
1. **Рефакторинг Frontend:** Разделить `index.html` на модули. Создать роутинг в FastAPI для отдельных вкладок (`/monitoring`, `/strategy`, `/optimization`).
2. **Переход на WebSockets:** Заменить медленный опрос REST API (`setInterval`) на WebSocket-канал для мгновенного получения свечей и статусов.
3. **Структура папок:** Создать директории `strategies/`, `configs/`, `market_data/`, `results/`, `logs/`.

### 🟡 ФАЗА 2: Движок Стратегий (Strategy Engine)
**Цель:** Научить сервер запускать внешние `.py` файлы.
1. **Базовый класс стратегии:** Написать `BaseStrategy.py` с методами `on_candle(candle)`, `get_state()`.
2. **Диспетчер процессов:** Реализовать запуск стратегии в отдельном процессе через `multiprocessing`.
3. **Передача настроек:** Научить сервер читать JSON из `configs/` и передавать его в процесс стратегии.
4. **Тестовая стратегия:** Написать простую стратегию (например, пересечение двух скользящих средних) для проверки движка.

### 🟠 ФАЗА 3: Режим Симуляции (Simulation Mode)
**Цель:** Реализовать "виртуальную торговлю" в реальном времени.
1. **Эмулятор времени:** Создать класс, который "кормит" стратегию свечами последовательно.
2. **Модель биржи:** Добавить учет комиссий (Maker/Taker) и проскальзывания.
3. **Состояние счёта:** Реализовать виртуальный баланс, расчет PnL, отслеживание открытых позиций.
4. **Интеграция с UI:** Вывод состояния счёта в правую панель Окна 1, сигнала стратегии — в центральный столбец.

### 🔴 ФАЗА 4: Режим Бэктеста (Backtest Mode)
**Цель:** Быстрый прогон по истории.
1. **Загрузчик данных:** Функция чтения CSV по диапазону дат.
2. **Ускоренный движок:** Отключение задержек, мгновенный прогон тысяч свечей.
3. **Генерация отчета:** Подсчет итоговых метрик (Sharpe Ratio, Max Drawdown, Profit Factor).
4. **Экспорт:** Сохранение списка всех виртуальных сделок в CSV.

### 🟣 ФАЗА 5: Окно Настроек и Конфигураций
**Цель:** Удобное управление JSON-шаблонами.
1. **CRUD для JSON:** Интерфейс создания, редактирования, удаления шаблонов в `configs/`.
2. **Валидация:** Проверка JSON на соответствие структуре, которую ожидает стратегия.
3. **Привязка к стратегиям:** Логика, которая показывает только те JSON, что подходят к выбранному `.py` файлу.

### 🔵 ФАЗА 6: Оптимизация и Генетический Алгоритм
**Цель:** Автоматический подбор параметров.
1. **Базовый ГА:** Реализация простого генетического алгоритма (селекция, скрещивание, мутация).
2. **Walk-Forward Validation:** Реализация сдвигающегося окна для защиты от переобучения.
3. **UI Оптимизации (Мое предложение):**
   - *Левая часть:* Настройки ГА (размер популяции, число поколений, диапазоны параметров).
   - *Центр:* Таблица "Зал Славы" (Топ-10 лучших наборов параметров).
   - *Правая часть:* График сходимости (обновляется после каждого поколения).
4. **Асинхронность:** Запуск оптимизации в фоне, чтобы не блокировать интерфейс.

### 🟤 ФАЗА 7: Система Логирования и Отчетности
**Цель:** Порядок в данных и ошибках.
1. **Логгер:** Настройка `logging` с ротацией файлов и разделением на `system.log`, `strategy_X.log`, `errors.log`.
2. **WebSocket для логов:** Трансляция важных логов прямо в Окно 4 в браузере.
3. **Архив результатов:** Автоматическое сохранение отчетов бэктестов в папку `results/YYYY-MM-DD/`.

### ⚫ ФАЗА 8: Отказоустойчивость и Масштабирование
**Цель:** Подготовка к продакшену.
1. **Переход на БД:** Замена CSV на SQLite (или PostgreSQL) для скорости и надежности.
2. **Мульти-активы:** Добавление возможности запускать стратегии на BTC, ETH и т.д. одновременно.
3. **Защита от падений:** Автоматический рестарт процессов стратегий при крахе, сохранение "снимков" состояния (checkpointing).
